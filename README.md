# Семейный бюджет

PWA на Vue 3 + Vite. Фронт хостится на GitHub Pages, данные лежат в Google Таблице, а API к ней — это Google Apps Script.

## 1. Бэкенд (Google Таблица)

1. Создайте новую Google Таблицу.
2. В ней откройте **Расширения → Apps Script**, удалите шаблонный код и вставьте содержимое `apps-script/Code.gs`.
3. Выберите функцию `setup` и нажмите **Выполнить**. Google попросит разрешения — выдайте их (на экране «Приложение не проверено» нажмите «Дополнительно → Перейти»).
   Функция создаст листы `Transactions`, `Recurring`, `Categories` (со стартовым набором категорий), `Accounts` и `Savings`, а семейный пароль выведет в **Журнал выполнения**.
4. Нажмите **Развернуть → Новое развертывание → Веб-приложение**:
   - «Запуск от имени»: **я**
   - «У кого есть доступ»: **все** (Anyone)
5. Скопируйте URL вида `https://script.google.com/macros/s/…/exec`.

> После правки `Code.gs` нужно сделать **Развернуть → Управление развертываниями → ✏️ → Новая версия**. Иначе продолжит работать старый код.

Категории редактируются в приложении: **⚙ в шапке → Категории расходов и доходов**. Иконки взяты из набора [Lucide](https://lucide.dev) (лицензия ISC). Список доступных иконок — в `src/icons.js`, в таблице хранится ключ иконки (колонка `icon`). Пароль меняется в **Project Settings → Script Properties → FAMILY_SECRET**.

Колонки в листах скрипт ищет по заголовкам. Если в новой версии появились колонки, он сам допишет их в конец листа, вручную ничего переделывать не нужно.

## 2. Фронт (GitHub Pages)

1. Создайте на GitHub **публичный** репозиторий и запушьте в него этот проект (ветка `main`).
2. Откройте **Settings → Pages → Source: GitHub Actions**.
3. После пуша workflow соберёт и опубликует сайт по адресу `https://<user>.github.io/<repo>/`.

## 3. На телефонах

1. Откройте сайт: на iPhone — в Safari, на Android — в Chrome.
2. Добавьте его на экран: iPhone — **Поделиться → На экран «Домой»**, Android — **⋮ → Установить приложение**.
3. В настройках приложения укажите URL скрипта и семейный пароль.

## Регулярные платежи

Вкладка **«Платежи»**: интернет, подписки, коммуналка, годовые платежи.

- Сумма бывает **постоянная** или **плавающая**. Для плавающей прогноз — медиана последних 6 оплат, а пока оплат нет, берётся оценка из шаблона.
- Отдельный вид — **ипотека** с досрочным погашением: в шаблоне общая сумма на месяц (платёж по графику + досрочка). При оплате вводится платёж по графику, остальное записывается как досрочное погашение (колонка `extra` в `Transactions`). На вкладке видно текущий платёж по графику, насколько он снизился с первой оплаты и сколько всего внесено досрочно.
- Периодичность: каждый месяц, раз в год или раз в N месяцев. Если указан день 31, в коротком месяце платёж переносится на последний день.
- Отмечать оплату нужно кнопкой на самом платеже. Так создаётся обычная трата, связанная с платежом (колонки `recurringId` и `period` в `Transactions`).
- На экране «Добавить» висят напоминания о просроченных платежах и о тех, до которых осталось 3 дня или меньше. На вкладке «Платежи» видны прогноз на следующий месяц и редкие платежи на ближайшие 60 дней.

## История и итоги

- На вкладке **«История»** под месяцем есть фильтр по категории. Пока он выбран, сверху видны число записей и сумма по категории.
- **«Итоги»** и экран **«Добавить»** помнят вкладку (расходы или доходы), выбранную в прошлый раз. Каждый телефон помнит свою.

## Копилки

Вкладка **«Копилки»** — только чтобы следить, сколько лежит на вкладах и накопительных счетах. С тратами и доходами она не связана.

- **Счета**: общая сумма и остаток на каждом счёте. Нажмите на счёт, чтобы внести операцию. Кнопка «Изменить список счетов» добавляет, переименовывает, переставляет и удаляет счета.
- Замок в списке счетов — для денег, которые нельзя снять в любой момент: **бессрочно** или **до даты** (например, конец вклада). Тогда сверху итог делится на «Можно снять» и «Заблокировано». В день окончания срока счёт снова считается свободным.
- Операции бывают трёх видов: **пополнение**, **снятие** и **остаток**. Остаток вносят, когда сверяются с банком, например после начисления процентов: он задаёт сумму на счёте заново.
- **История**: все операции по дням, с изменением и остатком после каждой. Её можно отфильтровать по счёту.
- В таблице это листы `Accounts` (счета) и `Savings` (операции). Остаток нигде не хранится, приложение пересчитывает его по истории.

## Как работает синхронизация

- Каждое изменение сразу сохраняется на телефоне и встаёт в очередь на отправку (счётчик на кнопке ⟳).
- Синхронизация запускается при открытии приложения, возврате в него, появлении сети и раз в минуту. Отправляется очередь, а в ответ приходят записи, изменённые после прошлой синхронизации.
- Удаление помечает запись флагом `deleted` в таблице, строка физически не стирается.
- Если две правки одной записи конфликтуют, побеждает та, что пришла на сервер последней.

## Локальная разработка

```bash
npm install
npm run mock     # локальный бэкенд: исполняет apps-script/Code.gs на эмуляции таблицы
npm run dev      # http://localhost:5173
npm run build
npm run icons    # пересоздать иконки из public/logo.svg
```
